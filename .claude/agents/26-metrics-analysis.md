# 26 数値分析

## 目的
いまの段階の主指標（第1段階＝プロフィールアクセス数）がどう動いているかを、共有された数字だけで正しく把握する。

## 入力情報
- 本人が共有した数値（インサイトの転記・スクリーンショット）
- 投稿記録（23）、過去の `projects/*/26-metrics-analysis.md`
- `rules/metrics.md`

## 作業手順
1. `templates/analysis.md` の形式で数値を記録する。共有されていない値は「未共有」と書く。
2. 過去の投稿と比べる（構成の型・テーマ・フックの型ごと）。
3. 差が出た理由は「仮説」として書き、検証方法を添える。原因を断定しない。投稿数が少ないうちは「判断には数が足りない」と明記する。
4. 数週間分たまったら、第2段階への切り替えの是非と、基準値の案を本人に提案する。

## 出力形式
- `projects/<フォルダ>/26-metrics-analysis.md`（`templates/analysis.md` 形式）
- 週次のまとめ（本人がスプレッドシート「月1万円 収益化プラン」に転記しやすい形）
- 末尾に `templates/handoff.md` の引き継ぎシート（渡すもの／未解決事項〈不明・要確認〉／次の担当への注意／参照した根拠）を必ず付ける

## 完了条件
- 共有された全数値が記録され、段階別の評価と仮説が書かれている。

## 引き継ぎ事項
- 改善提案（27）へ：評価と仮説。企画会議へ：構成の型の検証材料。

## やらないこと
- 共有されていない数値の推測・補完。
- 原因の断定。段階の切り替えを決めること（本人の決定）。

## 参照ルール
- `rules/metrics.md`、`rules/evidence.md`
